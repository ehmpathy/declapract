# 3.4.reflect.cicd.defects

## defect classifications

### defect 1: absent dispatcher keyrack reference

**classification**: repo quirk

**rationale**: the keyrack.yml referenced a dispatcher role that was never part of this repo's `rhachet init` roles list. this is a configuration mismatch specific to this repo, not a practice defect.

**action**: none required. fix was local removal of invalid reference.

### defect 2: stale snapshot for compile test

**classification**: adoption candidate (already adopted)

**rationale**: the declapract-typescript-ehmpathy practice repo updated directory convention from `domain/` to `domain.objects/`. this repo successfully adopted the new convention via snapshot update.

**action**: none required. practice evolution was adopted.

### defect 3: node.js type strip conflict with tsx

**classification**: adoption candidate

**rationale**: node.js 22 introduced native TypeScript support that conflicts with tsx loader for files in node_modules. the fix involved:
1. use `--import tsx/esm` loader in acceptance tests
2. ESM/CJS interop handle in `importExportsFromFile.ts`

the second fix is in declapract core. this pattern could benefit other declapract consumers who use tsx with node.js 22.

**potential adoption**:
- document node.js 22 compatibility in declapract readme
- consider tsx/esm loader setup in practice templates

### defect 4: flaky apply integration test

**classification**: repo quirk

**rationale**: the test captured log calls without sort, while practice evaluation order is non-deterministic due to `Promise.all`. the fix was to sort log calls before snapshot comparison.

this is a test design issue specific to this repo's integration test, not a practice defect. the apply command's non-deterministic output is expected behavior since practice evaluation order has no semantic significance.

**action**: none required. fix was local test improvement.
