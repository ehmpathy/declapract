# 3.3.repair.cicd.defects

## defect inventory

### defect 1: absent dispatcher keyrack reference

**what**: CI fails at keyrack firewall step with `BadRequestError: extended keyrack not found`

**how**: `.agent/keyrack.yml` extends `.agent/repo=bhuild/role=dispatcher/keyrack.yml` but this file does not exist.

```diff
# .agent/keyrack.yml
extends:
  - .agent/repo=bhrain/role=reviewer/keyrack.yml
- - .agent/repo=bhuild/role=dispatcher/keyrack.yml
  - .agent/repo=ehmpathy/role=mechanic/keyrack.yml
```

**why**: the dispatcher role is absent from the `rhachet init` command in package.json:
```
"prepare:rhachet": "rhachet init --keys --hooks --roles mechanic behaver driver reviewer librarian ergonomist architect"
```
dispatcher is not in the roles list, so the keyrack file it would provide is never created.

**fix**: removed the dispatcher keyrack reference from extends since the role is not used in this repo.

### defect 2: stale snapshot for compile test

**what**: compile.integration.test.ts snapshot failed with path mismatch.

**how**: upgrade changed directory structure practice from `domain/` to `domain.objects/`.

```diff
- "examples/typescript/src/domain/index.ts",
+ "examples/typescript/src/domain.objects/index.ts",
```

**why**: the declapract-typescript-ehmpathy practice repo was updated to use `domain.objects/` instead of `domain/` as the directory name for domain objects. this is an intentional practice change.

**fix**: updated snapshot with `--resnap` flag.

### defect 3: node.js type strip conflict with tsx

**what**: acceptance test fails with `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING` when CLI loads `.declapract.ts` files from node_modules.

**how**: node.js 22 has native TypeScript support that auto-detects `.ts` files. when declapract loads `.declapract.ts` practice files from node_modules via tsx, node.js tries to use its native type strip feature but refuses because the files are in node_modules.

```
Error [ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING]: ...
```

**why**: node.js 22 added `--experimental-strip-types` which auto-detects `.ts` files. this conflicts with tsx's own TypeScript handler for files in node_modules.

**fix**: two-part fix:
1. in acceptance test, use `tsx/esm` loader via `--import tsx/esm` to properly handle dynamic imports of `.declapract.ts` files
2. in `importExportsFromFile.ts`, handle ESM/CJS interop by check if exports are on `mod.default` (tsx wraps ESM exports in a default object when loaded via dynamic import)

### defect 4: flaky apply integration test

**what**: CI intermittently fails on `apply.integration.test.ts` with snapshot mismatch for practice evaluation order.

**how**: the test captures `logSpy.mock.calls` and compares to a snapshot. practice evaluation order varies per run.

```diff
-     "  ✓ evaluated practice:prettier",
+     "  ✓ evaluated practice:util-sleep",
```

**why**: `Promise.all` and file system iteration do not guarantee order. each run may produce different order for same practices.

**fix**: sort log calls alphabetically before snapshot comparison to ensure deterministic output.
