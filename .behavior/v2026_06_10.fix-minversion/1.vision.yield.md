# 1.vision

add `.ifInstalled()` modifier for version checks

---

## the outcome world

### before

practice maintainer wants to enforce "if you use `with-simple-cache`, it should be >= 0.16.2" across all repos.

today, they face a dilemma:
- use `check.minVersion('0.16.2')` → repos without `with-simple-cache` fail (false positive)
- use `optional: true` → only skips if the *file* is absent, not if the *dependency* is absent
- use custom `FileCheckFunction` → works but verbose, unmaintainable, duplicated

so they either:
1. create noisy false positives
2. write verbose custom functions for each optional dependency
3. give up and don't enforce version minimums for optional deps

### after

```json
{
  "dependencies": {
    "with-simple-cache": "@declapract{check.minVersion('0.16.2').ifInstalled()}"
  }
}
```

repos that don't use `with-simple-cache` → pass (skipped)
repos that use `with-simple-cache` >= 0.16.2 → pass
repos that use `with-simple-cache` < 0.16.2 → fail with clear message

### the "aha" moment

"I can enforce version minimums for optional dependencies without custom functions or false positives."

## user experience

### usecases

1. **optional cache library** — enforce minimum version of cache libs only in repos that use them
2. **optional test framework** — ensure jest >= 29.0.0 only in repos that use jest
3. **optional formatter** — ensure prettier >= 3.0.0 only in repos that use prettier

### contract inputs & outputs

**input**: declaration in best-practice package.json
```json
{
  "dependencies": {
    "with-simple-cache": "@declapract{check.minVersion('0.16.2').ifInstalled()}"
  }
}
```

**output on check**:

| target repo has | check result |
|-----------------|--------------|
| no `with-simple-cache` key | pass (skipped) |
| `with-simple-cache: "0.16.2"` | pass |
| `with-simple-cache: "0.17.0"` | pass |
| `with-simple-cache: "0.15.0"` | fail: "expected >= 0.16.2, found 0.15.0" |
| `with-simple-cache: "link:."` | pass (linked deps always pass) |

**output on fix**:

when `.ifInstalled()` is present and dependency is absent → no fix applied (dep not added)
when `.ifInstalled()` is present and dependency is below min → fix applied (version bumped)

### timeline

1. practice maintainer adds `.ifInstalled()` modifier to version check
2. `declapract plan` runs across org repos
3. repos without the dep pass silently
4. repos with outdated versions are flagged
5. `declapract apply` bumps versions in flagged repos

## mental model

### how users describe it

"check version only if installed" or "skip if not present"

### analogies

- **CSS media queries**: `@media (min-width: 768px)` only applies if screen is wide enough
- **shell conditionals**: `command -v git && git status` — only run git status if git exists
- **optional chaining**: `obj?.prop?.method()` — only call if path exists

### terms

| user term | internal term |
|-----------|--------------|
| "if installed" | `ifInstalled()` modifier |
| "skip if absent" | pass when `foundValue === undefined` |
| "optional dependency check" | version check with `ifInstalled()` modifier |

## evaluation

### how well does it solve the goals?

| goal | solved? |
|------|---------|
| enforce min version for optional deps | yes |
| no false positives for absent deps | yes |
| no custom functions needed | yes |
| composable for future modifiers | yes |

### pros

- declarative: no custom code needed
- composable: fluent chain enables future modifiers (`.warnOnly()`, etc)
- consistent: same pattern as extant `check.minVersion()`
- minimal: one modifier, one behavior change

### cons

- new syntax to learn (but mirrors extant pattern)
- fix behavior needs consideration (what to do when absent?)

### edgecases and pit-of-success

| edgecase | behavior | rationale |
|----------|----------|-----------|
| dep key absent | pass (skip) | that's the point |
| dep value is `null` | pass (skip) | treat as absent |
| dep value is `undefined` | pass (skip) | treat as absent |
| dep value is `"link:."` | pass | linked deps always pass (extant behavior) |
| dep value is semver range `"^1.0.0"` | fail | ranges not valid semver (extant behavior) |
| nested in devDependencies | works | recursive eval handles all dep sections |

## open questions & assumptions

### assumptions made

1. `.ifInstalled()` only makes sense for `check.minVersion()` (not other check types)
2. fix phase should skip absent deps (not add them)
3. fluent chain pattern is the right extension mechanism

### questions that remain

1. should there be a `.required()` counterpart? [answered: no — would be a no-op, default is required]

## what is awkward?

### what feels off?

- the name `ifInstalled` implies action ("install if not"), but the behavior is "skip if not installed"
- alternative names: `.optional()`, `.ifPresent()`, `.skipIfAbsent()`
- `.ifInstalled()` is domain-specific to package deps; `.ifPresent()` would be more general

### where does design fight mental model?

- users might expect `.ifInstalled()` to *add* the dependency if absent
- need clear docs: "skip check if absent, do not add"

### uncomfortable tradeoffs

- `.ifInstalled()` vs `.optional()` — former is domain-specific, latter might conflict with file-level `optional: true`
- keeping `.ifInstalled()` avoids namespace collision with extant `optional` concept
