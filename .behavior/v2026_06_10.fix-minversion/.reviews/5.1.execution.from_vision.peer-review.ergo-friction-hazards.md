# blocker.1: Error paths for minVersion check failures not snapped

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.execution/architect/rule.forbid.friction-hazards.md

**locations**:
- src/domain.operations/declaration/readPracticeDeclarations/readPracticeDeclaration/getFileCheckDeclaration/checkMethods/composableActions/checkContainsJSON.test.ts

Multiple tests for error paths (when declared JSON check fails due to minVersion or absent deps) catch the error but only assert toContain without toMatchSnapshot(). Per the rule, every error path a user can hit must be acceptance tested and snapped so the actual user-facing error message (the diff) is visible to reviewers and protected from drift. Unsnapped friction paths will ship broken or unclear errors.

Affected tests include self-dep filter failure, baseline absent dep, and some .ifInstalled cases. Fix by adding expect((error as Error).message).toMatchSnapshot() to all such catch blocks.

**snippet**:
```ts
      } catch (error) {
        expect((error as Error).message).toContain('toContain');
        expect((error as Error).message).toContain('domain-objects');
      }
```

# blocker.3: Confusing error presentation for minVersion check failures

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.execution/architect/rule.forbid.friction-hazards.md

**locations**:
- src/domain.operations/declaration/readPracticeDeclarations/readPracticeDeclaration/getFileCheckDeclaration/checkMethods/composableActions/checkContainsJSON.ts

When a minVersion check fails, the code returns a string like `a version greater than or equal to '1.0.0'` to be used in the declared side of the diff. This produces non-actionable, confusing output for the end user (the practice author or consumer) who sees the weird string in their error instead of a clear message like 'version 0.8.21 does not meet minimum 1.0.0; update the package.json dependency'. This is unaddressed ergonomic friction and violates error clarity and output consistency requirements.

The mechanism relies on checkContainsSubstring producing a 'good looking diff' but the content itself is a friction hazard. Change to throw a direct, clear, actionable error instead of hijacking the declared value for diffing.

**snippet**:
```ts
  // if foundValue does not match it, return the error message
  if (!passesMinVersionCheck)
    return `a version greater than or equal to '${minVersion}'`;

  // if it does match it, then return the value we found (so that there's no diff due to this one)
  return foundValue;
```
