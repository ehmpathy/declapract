# vision: fix(glob): respect .gitignore patterns when scanning files

## the outcome world

### before
```
$ time declapract plan

practice:tests took 134+ seconds
scanning .agent/.cache/ with nested node_modules...
scanning .terraform/ with thousands of state files...
scanning dist/ with compiled output...

real    2m14.821s
```

### after
```
$ time declapract plan

practice:tests took 0.8 seconds
(ignored .agent/.cache/, .terraform/, dist/ - all in .gitignore)

real    0m0.842s
```

### the "aha" moment

when you run `declapract plan` and it completes in under a second instead of over two minutes — because it finally acts like `git` and ignores what you told it to ignore.

## user experience

### usecases

| usecase | before | after |
|---------|--------|-------|
| run `declapract plan` in repo with large .gitignore | 2+ minutes, scans everything | <1 second, respects .gitignore |
| evaluate practices on CI | timeout risk | fast, predictable |
| add new gitignored dir | manual edit to declapract internals? | just add to .gitignore |

### contract inputs & outputs

**no contract change required** — this is an internal performance fix. the glob function already has an `ignore` option; we're just populating it from `.gitignore` instead of hardcoding `['node_modules/**']`.

### timeline

1. user runs `declapract plan` or `declapract apply`
2. declapract reads `.gitignore` from project root
3. glob uses those patterns to skip directories during traversal
4. massive speed improvement, identical results (for files git tracks)

## mental model

### how users would describe this

> "declapract only looks at files git tracks"

or

> "declapract respects my .gitignore just like git does"

### analogies

- like how `rg` (ripgrep) respects .gitignore by default
- like how eslint and prettier respect .gitignore
- the opposite of `find .` which scans everything blindly

### terms

| user term | our term |
|-----------|----------|
| "ignored files" | gitignore patterns |
| "scan" | glob traversal |
| "skip" | ignore option |

## evaluation

### how well does it solve the goals?

| goal | solved? |
|------|---------|
| 134+ second scan → sub-second | yes |
| no contract change | yes |
| respects all .gitignore patterns | yes |
| handles nested .gitignore files | depends on implementation |

### pros

- **massive performance gain** — orders of magnitude faster for repos with large gitignored dirs
- **zero config** — works automatically if project has .gitignore
- **matches user expectations** — "why is declapract scanning node_modules?!"
- **aligns with git ecosystem** — eslint, prettier, rg all do this

### cons

- **slight behavior change** — files in gitignored directories are no longer checked
- **dependency addition** — need `globby` or `ignore` package
- **edge case: deliberately checking gitignored files** — currently not a use case, but worth noting

### pit of success

- gitignore support is opt-out (not opt-in) — fast by default
- if someone truly wants to check gitignored files, they can use git negation patterns (`!important-dir/`)

## open questions & assumptions

### assumptions

1. **no one wants to check gitignored files** — the whole point of gitignore is "don't track these"
2. **project has .gitignore at root** — if not, behavior is unchanged
3. **globby/ignore packages are reliable** — well-maintained, battle-tested

### questions to validate with wisher

## groundwork

### external research

**glob v11 ignore options** (verified via npm docs):
- `ignore` option accepts string[], but does NOT read .gitignore automatically
- must manually provide patterns or use external library
- source: https://github.com/isaacs/node-glob#readme

**globby gitignore support** (verified via npm docs):
- `gitignore: true` option respects .gitignore patterns
- searches from cwd downward, checks parent directories up to repo root
- gitignore patterns take priority over user patterns
- source: https://github.com/sindresorhus/globby#readme

**globby health and API compatibility** (verified 2026-06-11):
- version: 16.2.0
- last publish: 2026-03-27 (actively maintained)
- `dot` option: yes, supported
- `onlyFiles` option: yes, equivalent to glob's `nodir: true`
- return type: `Promise<string[]>` — same as glob
- API is compatible with current glob usage

**ignore package** (verified via npm docs):
- specifically for parsing .gitignore rules
- used by eslint, gitbook, many others
- source: https://www.npmjs.com/package/ignore

### internal research

**current implementation** (`src/domain.operations/usage/evaluate/evaluateProjectAgainstFileCheckDeclaration.ts:59-64`):

**also affected** (`src/utils/filepaths/listFilesInDirectory.ts:12-16`):
```ts

  cwd: directory,

```

**extant test for node_modules** (`evaluateProjectAgainstPracticeDeclaration.integration.test.ts:475`):
- test asset: `example-project-passes-testing-with-bad-practices-in-ignored-dirs`
- verifies node_modules is ignored, but .gitignore patterns are NOT tested

## what is awkward?

### the tradeoff

we're trading "check everything" for "check what git tracks". this is the right tradeoff for 99.9% of users, but technically changes behavior.

### where the design fights mental model

nowhere — this aligns perfectly with how users expect git-based tools to work.

### uncomfortable tradeoffs

- adding a dependency (globby or ignore) for something that "should" be built-in
- deciding whether to support nested .gitignore (complexity vs correctness)

## proposed implementation

### option A: use globby (recommended)

replace `glob` with `globby`:

```ts
import { globby } from 'globby';

const pathsFoundByGlob = await globby(check.pathGlob, {
  cwd: project.getProjectRootDirectory(),
  dot: true,
  onlyFiles: true,
  gitignore: true,  // ← respects .gitignore automatically
});
```

**pros**: simplest, battle-tested, handles nested .gitignore
**cons**: new dependency, slightly different API

### option B: use ignore package with extant glob

parse .gitignore and pass patterns:

```ts
import ignore from 'ignore';
import { readFileSync } from 'fs';

const gitignoreContent = readFileSync('.gitignore', 'utf-8');
const ig = ignore().add(gitignoreContent);

const allFiles = await glob('**/*', { cwd, dot: true, nodir: true });
const trackedFiles = allFiles.filter(file => !ig.ignores(file));
```

**pros**: no change to glob import, more control
**cons**: doesn't prevent traversal (slower), more code

### recommendation

**option A (globby)** — simpler, faster, more correct. globby is maintained by sindresorhus and widely used.

## test plan

### heavy tests for gitignore respect

1. **test: ignores patterns from root .gitignore**
   - create test asset with `.gitignore` containing `dist/`, `*.log`
   - verify glob does NOT return files in `dist/` or `*.log` files

2. **test: handles complex patterns**
   - negation patterns: `!important.log`
   - directory patterns: `build/`
   - glob patterns: `**/*.tmp`
   - comment lines: `# this is a comment`

3. **test: handles missing .gitignore gracefully**
   - project without .gitignore should still work (scan everything)

4. **test: handles empty .gitignore gracefully**
   - project with empty .gitignore should still work (scan everything)

5. **test: performance regression test**
   - create test asset with 1000+ files in gitignored directory
   - verify glob completes in <100ms (not 134+ seconds)

6. **test: nested .gitignore files (if supported)**
   - create test asset with nested `.gitignore` in subdirectory
   - verify patterns from nested gitignore are respected

7. **test: gitignore with node_modules negation**
   - test asset `example-project-passes-testing-with-bad-practices-in-ignored-dirs` has `!node_modules`
   - verify this negation is respected (files in node_modules ARE scanned)

8. **test: dot directories with gitignore**
   - `.hidden/` directory that is gitignored should be skipped
   - `.hidden/` directory that is NOT gitignored should be scanned (current behavior preserved)

### integration test structure

```ts
describe('listFilesInDirectory', () => {
  describe('gitignore support', () => {
    it('should ignore files matching .gitignore patterns', async () => {
      const directory = `${testAssetsDirectoryPath}/example-project-with-gitignore-patterns`;
      const paths = await listFilesInDirectory({ directory });

      // should NOT include gitignored files
      expect(paths).not.toContain('dist/compiled.js');
      expect(paths).not.toContain('debug.log');
      expect(paths).not.toContain('temp/scratch.tmp');

      // SHOULD include non-gitignored files
      expect(paths).toContain('src/code.ts');

      // SHOULD include negation pattern files
      expect(paths).toContain('important.log');
    });

    it('should complete quickly with large gitignored directories', async () => {
      const directory = `${testAssetsDirectoryPath}/example-project-with-large-gitignored-dir`;
      const start = Date.now();
      const paths = await listFilesInDirectory({ directory });
      const elapsed = Date.now() - start;

      expect(elapsed).toBeLessThan(100); // should be <100ms, not 134+ seconds
      expect(paths).not.toContainEqual(expect.stringContaining('.cache/'));
    });

    it('should work without .gitignore file', async () => {
      const directory = `${testAssetsDirectoryPath}/example-project-without-gitignore`;
      const paths = await listFilesInDirectory({ directory });

      expect(paths).toContain('src/code.ts');
    });
  });
});
```
